# @rumtelo/i18n

Internationalization for Rumtelo: `next-intl` + TypeScript sources under `translations/` → generated JSON in `languages/`.

**Locale list:** contracts `Locale` in `@rumtelo/contracts` (`common.enums`) — single source of truth. Intl tags are `Lowercase<Locale>`.

## Source of truth

Same flow as Galighticus:

- **Edit copy** under [`translations/`](./translations/) (`common/`, `ui/`, `features/`, `pages/`). That English is the lead.
- **Do not edit** [`languages/*.json`](./languages/). Those files are generated.
- **Wrong translation:** fix the exact string in [`translations/overrides.ts`](./translations/overrides.ts) (locale + dot path). That is applied after DeepL and does not spend quota on unchanged English.
- After changing `translations/`, run:

```bash
pnpm i18n:gen
```

That rebuilds every `languages/*.json` from the TypeScript source. Unchanged English sentences are reused from [`cache/`](./cache/) (hash of the English text + locale). A changed English sentence misses the cache and is translated again with DeepL (`DEEPL_API_KEY` in `packages/i18n/.env`).

## Usage

```tsx
import { useTranslations } from '@rumtelo/i18n';

const t = useTranslations();
t('pages.shell.settings');
t('features.brand.tagline');
```

Apps load messages via `i18n/request.ts` + `next-intl` plugin (see `apps/application/i18n/request.ts`).

## Status

- **EN source of truth:** `translations/**/*.ts` → `pnpm i18n:gen`.
- **Locales:** generated by that same command (DeepL + cache + overrides).
- **Wired:** Application and website UI chrome use `next-intl`.
- **Still EN by design:** `@rumtelo/ui` defaults, API freeform fields, learn catalog merchants, Stripe catalog, throw messages.
